# Architecture

Tursora is one Swift executable target, `app/Sources/Tursora`, split into `Model/` (no AppKit views, headlessly testable) and `UI/` (AppKit). SPM pins SwiftTerm 1.15.0 for the terminal and Sparkle 2.9.6 for software updates. Tursora's interface is built in AppKit code, without application nibs or storyboards; Sparkle supplies its own bundled updater interface and helpers. This document is the code map; the intended behaviour is in [SPEC.md](SPEC.md), the reasons in [DECISIONS.md](DECISIONS.md).

## 1. Object graph at runtime

```
NSApplication
└─ AppDelegate                          shared LocalFileProvider + PlacesModel
   └─ MainWindowController ×N           window, toolbar, BrowserHost
      └─ contentSplitController         horizontal divider: browser above, optional terminal below
         ├─ splitViewController         vertical divider
         │  ├─ SidebarViewController    PlacesModel outline + optional FoldersPanelController below
         │  ├─ TabsController           tab bar, TabPages, split drop overlay
         │  └─ PreviewPanelController   optional docked preview, appended last (D83)
         │     └─ TabPage ×tabs         1–2 panes, activeIndex
         │        └─ BrowserViewController ×pane
         │           ├─ DirectoryModel, NavigationHistory, DirectoryWatcher
         │           ├─ BreadcrumbBar, SearchPanelController
         │           ├─ fileView: FileViewing = FileListViewController | IconGridViewController | ColumnViewController
         │           ├─ StatusBarView, active indicator, error label, context menu
         │           └─ Quick Look data source / delegate
         └─ TerminalPanelController?    window-retained SwiftTerm PTY, attached only while visible
InfoWindowController ×open              registry + Inspector
TransferTasksWindowController.shared     retained transfer tasks, per-task controls and nonmodal conflicts
SettingsWindowController                General / Shortcuts / Terminal / Updates over injected settings stores
WorkspaceSessionStore.shared            private window/tab/pane JSON; AppDelegate captures and schedules saves
AppUpdater.shared                       one Sparkle controller; injectable driver for headless tests
ServerConnectionController              shared address window + NetFS request
ArchiveWorkspace.shared                retained ZIP snapshots; logical locations in ordinary panes
```

- **`main.swift`** creates `NSApplication`, an `AppDelegate`, sets `.regular` activation policy, runs.
- **`AppDelegate`** owns the `LocalFileProvider`, `PlacesModel`, `windowControllers`, injected preferences/view-properties/session stores and the workspace save debounce. `newWindow(at:)` installs `wc.onClose` and `wc.onSessionChanged`; optional ordering/cascading lets `beginWorkspaceSession` restore all saved windows before choosing focus. Startup opens Home only when no explicit or restored browser window exists. In smoke mode startup instead supplies an isolated window to `SmokeTest.run(wc)`. Quit first checks retained terminals in every window and obtains confirmation when activity requires it. Only then does `prepareWorkspaceForTermination` capture and synchronously save before transfer cleanup, Info edits, owned terminal shutdown or temporary ZIP cleanup. Cancelling does not set termination state or cancel transfers. Preference changes update menus and enable/clear session persistence.
- **`AppUpdater`** starts once after the first window is created, routes the application menu and Settings manual-check command, and validates actions against Sparkle's current availability. Its shared factory never constructs Sparkle during smoke tests or for a bare SPM executable. Settings and test delegates can inject their own driver without networking.
- **`DockMenuCommand` / `DockMenuDirectories` / `DockMenu`** separate fixed destinations from native menu construction. `AppDelegate.applicationDockMenu` returns New Window, Downloads and Applications with explicit targets and distinct selectors, since Dock dispatch may pass a nil sender. Each delegates to `newWindow(at:)` and activates the app; existing pane state is never the destination. Standard Dock/window entries remain system-managed. `DockMenuSmokeTests` verifies actual action dispatch and window ownership using isolated directories in every file view.
- **`MainWindowController`** (one per window) owns the `NSWindow`, a vertical-divider split (sidebar + tabs) inside a horizontal-divider split (browser + optional terminal), the `NSToolbar` (it is the delegate), `SidebarViewController` and `TabsController`. It **is** the `BrowserHost` (`tabs.host = self`) and the delegate of the toolbar's `NSSearchToolbarItem`. It holds `backButton`/`forwardButton` (`LongPressMenuButton`), `viewModeControl`, `searchItem`, and local `NSEvent` routing through `ShortcutDispatcher` plus mouse buttons 4/5. `MainMenu` installs an application-wide input-protection monitor so Control/function keys in any text editor or SwiftTerm reach the native view before menu key equivalents.
- **`TabsController`** owns, top to bottom in one `NSStackView`: the always-visible `TabBarView` and a container holding every `TabPage` view plus a `SplitDropOverlay`. Its computed `addressBar` aliases the active browser's bar for window navigation commands; it owns no shared path editor. State: `pages`, `currentIndex`, `closedTabs` (max 10). Callbacks out: `onCurrentLocationChanged`, `onTabsChanged`, `onWorkspaceSessionChanged`. Context actions retain the clicked page's identity and resolve its current index at execution. Closing a background page preserves the surviving active page; only removing the active page chooses its neighbor. Workspace restoration builds fresh pages and clears the closed-tab pool, without sharing navigation or undo contexts across launches.
- **`TabPage`** = one tab: 1–2 `BrowserViewController`s in a vertical-divider `NSSplitView` (it is the delegate), `activeIndex`, a custom tab name, requested split fraction, and a click monitor that activates whichever pane was clicked. Automatic titles show both physical sides separated by a vertical bar; a nonempty custom name overrides that title. Callbacks out: `onActivePaneChanged`, `onPaneLocationChanged`, `onWorkspaceSessionChanged`. The resize delegate applies the stored ratio even to hidden pages; temporary minimum pane widths do not replace that ratio.
- **`BrowserViewController`** = one pane. Wraps the supplied provider in `ArchiveFileProvider`, backed by the shared `ArchiveWorkspace`. Owns a `DirectoryModel`, a `NavigationHistory`, a `BreadcrumbBar` above its search panel and file content, the three file views (current one as `fileView: FileViewing`), `StatusBarView`, the pane's context menu (it is the `NSMenuDelegate`) and a `DirectoryWatcher`. Path callbacks capture this browser, activate it and navigate only it. `weak var host: BrowserHost?` reaches the window.
- **`FileViewing`** is the protocol all three file views implement; the browser is the sole consumer of their closures.
- **Chrome** is split by ownership: the toolbar, sidebar and hidden window title reflect `tabs.currentPage.active`; each browser owns its breadcrumb and completion popup, so both split paths stay visible. Switching tabs or panes dismisses the departing path edit and popup without submitting unfinished input. The tab bar presents both pane captions in physical order, with full logical paths in tooltips. The terminal belongs to the window, not a tab: location updates change its pending restart destination, never write commands into its PTY. Hiding detaches its visible panel while the window retains the controller, output and process; disabling terminal access uses the same hiding path. Showing reattaches the existing session, and changed shell preferences wait for an explicit new start/restart. In an archive, the window represents the source ZIP and the terminal destination is its containing directory, never a temporary snapshot.

## 2. Per file

### Model/

| File | Responsibility |
|---|---|
| `AppUpdater.swift` | App-wide update service over `AppUpdateDriver`; the production driver wraps `SPUStandardUpdaterController`. Exposes persisted automatic-check/download settings, manual-check availability and last-check status; KVO changes post `AppUpdater.didChange`. Starts without overwriting saved choices and reports configuration failure inline. |
| `FileProvider.swift` | `protocol FileProvider` (`listDirectory(_:)`, `homeURL`, `displayName(for:)`) — the single filesystem seam; `LocalFileProvider` implements it with `FileManager`. | `FileItem.swift` | Immutable value for one listing entry: `url, name, isDirectory, isPackage, isHidden, isSymlink, size, modificationDate, creationDate, accessDate, addedDate, contentType`, all read once via `resourceKeys`. Derived: `isNavigable`, `displayName` (extension preference only), `icon(size:)`, `kindDescription`, `displaySize`, `displayDate`. Identity and rename always use `name` / URL. Archive entries retain a logical `url`, physical `contentURL`, access state and session; `readableContentURL` revalidates containment before use. Metadata is cached, while content access remains guarded. |
| `DirectoryModel.swift` | `FileNode` (class, identity-stable across reloads, keyed by URL) and `DirectoryModel`: `url`, `allNodes`, `nodes`, `groups`, `generation`, and the arrangement inputs `showHidden`, `nameFilter`, `groupKey`, `sortKey`, `ascending` (each `didSet` → `resort()`). `load(_:completion:)` lists off-main with a `loadToken` guard and merges into existing nodes; `reload`, `setSort`, `loadChildren(of:refresh:)` (synchronous), `node(for:)`, `matches(_:filter:)` (wildcards when `*`/`?`). Private `arrange` = hidden filter + name filter + sort, recursing into loaded children. Never mutates the filesystem. |
| `DirectoryWatcher.swift` | FSEvents wrapper (file events, 0.25 s latency, dispatched on main). Also defines `Notification.Name.tursoraDirectoriesChanged` and `enum DirectoryChanges` with `post(_:renamed:)` and `affected(sources:destination:)`. |
| `Grouping.swift` | `GroupKey` (nine keys including None; Tags excluded by design), `GroupNode` (title + nodes + sort order), and the pure `Grouping.split(_:by:now:)` with `nameBucket`, `kindBucket`, `applicationBucket`, `dateBucket`, `sizeBucket`. | `NavigationHistory.swift` | Linear `entries` + `index`; `push` (dedupes the current URL, truncates forward, trims to 100), `goBack`, `goForward`, `go(to:)`, `recordViewState(selectedName:scrollOffset:)`, `backEntries`/`forwardEntries` for the long-press menus. Knows nothing about views. |
| `FileOperations.swift` | Filesystem mutation facade: naming, rename/trash/delete, asynchronous `transfer` returning a controllable `TransferTask`, and reversible transfer-journal replay. | `BatchRename.swift` | Pure Finder "Rename Finder Items" rules: `Mode` (`.replace`/`.add`/`.format`), `Position`, `FormatKind`, `Entry` (directory + name + injected date), `plan(_:mode:)`, `validate(_:for:siblings:caseSensitive:)` → `Problem` (`.empty`/`.invalid`/`.taken`, Finder's wording), `menuTitle(count:)`. Replace rewrites the whole name; Add and Format keep the extension. Collisions are scoped per directory and ignore the names the batch itself frees, so chains, swaps and case-only renames validate. No UI, no I/O. |
| `BatchRenameOperations.swift` | `FileOperations` extension: `RenameRequest`, `siblingNames(in:)`, `renameBatch(_:)` — validates first, skips unchanged names, moves every item through a unique temporary and then to its final name so intermediate states cannot collide, refuses to overwrite an item outside the batch and rolls the whole batch back on failure — and `reverseRenameBatch(_:)` for undo. Also `DirectoryChanges.postRenames(_:)`. The single-item `FileOperations.rename` stays on `URLResourceValues` (case-only renames) and must not be used for batches: it silently overwrites an existing sibling. |
| `TransferTask.swift` | Source normalization through `FileOperations.mutationSources`, fixed source/destination context, synchronized snapshots and pause/cancel acknowledgements, lifecycle states, deterministic transfer test seams. |
| `TransferEngine.swift` | Worker-only traversal and bounded data writes, metadata copying, exclusive staged publication, per-task conflict policy, source retirement, and reversible rename journals with retained same-volume recovery storage. |
| `FileInfo.swift` | Every fact behind Get Info, computed headlessly: `whereString`, `dateString`, `Size` + `computeSize(of:countingChildren:update:)` → cancellable `SizeCalculation`, `sizeString`/`headerSizeString`, `isLocked`/`setLocked`, `hasHiddenExtension`/`setHiddenExtension`, `comment`/`setComment` (xattr `com.apple.metadata:kMDItemFinderComment`), `moreInfo` (Spotlight), `bundleInfo`, `volumeInfo`, `original`, `applications(toOpen:)`, `Permissions`/`Privilege`/`Who`, `privilege`, `mode(_:setting:for:isFolder:)`, `setMode`, `accessSummary`, `fileID`/`sibling(of:withFileID:)`, `kind`, `summaryKind`. Reads flags through `FileManager.attributesOfItem`, not URL resource values (D15). |
| `PlacesModel.swift` | Sidebar data: `Section`/`Place`, rebuilt from `builtIns()` + user paths in one persisted order list, plus mounted volumes. `favouriteIndex(of:)`, `isFavourite`, `addFavourite(_:at:)`, `removeFavourite`, `moveFavourite(from:to:)`, `resetFavourites`, `isEjectable`. Posts `PlacesModel.didChange`; observes `NSWorkspace` mount/unmount/rename. Locations ends with a non-removable `Trash` place from `TrashLocation.userTrash()`. |
| `PathCompleter.swift` | Path resolution and directory completion, including prepared logical ZIP locations. `resolveNavigationLocation(_:cwd:home:workspace:)` additionally accepts a pending ZIP directory candidate; the browser must prepare and validate it before navigation. `resolveDirectory` remains strict for prepared children; completion skips packages and uses safe archive entries. |
| `ThumbnailProvider.swift` | Singleton text / Quick Look thumbnail cache: `canPreview(_:)`, `thumbnail(for:size:scale:completion:)` returns a cached image synchronously or calls back on main; `NSCache` keyed by path·size·scale·mtime·bytes, coalesced `pending`, remembered `unsupported`. Background text reads/rendering fall back to Quick Look; callback publication validates the archive-readable URL again. Both file views invalidate pending delivery on reload / zoom / preview changes; grid cells also bind a UUID per configuration. |
| `ContentScanner.swift` | Reads a file and says whether it holds a piece of text, for content search without the index (D85). Bounded (1 MB read, 64 MB candidate) and opened defensively — non-blocking with an `fstat` guard, so a FIFO in the searched tree cannot block the walk. A byte-order mark is honoured before the NUL binary test. A pure function of bytes apart from `scanFile`, so it is checked without the filesystem. |
| `MarkdownRenderer.swift` | Markdown to styled text as a pure function. `AttributedString(markdown:)` gives semantics only — no separators, fonts or colour — so block boundaries, heading sizes, list markers, indents, the code face and `NSTextTable` geometry are all synthesised here (D81). |
| `TextThumbnailRenderer.swift` | Bounded regular-file reads (64 KiB by default, more when a caller asks; UTF-8 or BOM UTF-16), strict text decoding, caller-supplied excerpt limit, 3:4 paper and 7-10 pt CoreText rendering at the requested backing scale. No file access in views. |
| `ZoomLevel.swift` | `ViewMode`, the two zoom ladders, `defaultIndex`, `clamp`, `previewThreshold = 32`. Navigation and view changes write per-directory properties, never global preferences. |
| `DirectoryViewProperties.swift` | `DirectoryViewProperties` holds mode, per-mode zoom, sort/direction, group/last-group, hidden files and previews, with tolerant Codable decoding and zoom clamps. `DirectoryViewPropertiesStore` owns independent defaults, per-directory records and `perDirectory`/`unified` policy, immediate in-memory reads, canonical local path keys, serial coalesced atomic persistence, `flush`, explicit default/policy/reset notifications, and asynchronous write-failure/recovery status. |
| `AppPreferences.swift` | Persistent extension-label display, a shared `ShortcutStore` with a legacy filter facade, and default-on terminal/ZIP flags with preserved explicit opt-outs. Explicit writes persist even if they match the effective default; notifications occur only for effective changes. Injectable `Store` and `.tursoraPreferencesChanged`; no shell/archive work is triggered by a preference getter. |
| `ArchiveOperations.swift` | `FileOperations` ZIP creation/extraction, isolated staging, containment validation, exclusive publication, metadata/quarantine preservation. `ArchivePreparationCancellation` coordinates an owned Process and cancellation checkpoints; the worker waits for exit before removing output. |
| `ArchiveBrowsingSession.swift` | Private extracted snapshot for read-only browsing, containment-checked navigation/opening, cleanup through `FileOperations`; never replaces the original ZIP. |
| `ArchiveWorkspace.swift` | Thread-safe shared session registry, coalesced asynchronous preparation with independently cancellable subscriptions, job identities and a main-thread shutdown barrier; logical/readable URL mapping and application-exit cleanup. `ArchiveFileProvider` routes archive listings and preserves logical `FileItem` identity. |
| `WorkspaceSession.swift` | Codable window/tab/pane snapshots and bounded, lossy loading; local URL syntax validation without existence checks or symlink resolution. `WorkspaceSessionStore` uses a private atomic JSON file, exposes load/save failures and retains previous data on failed writes. | `ServerConnection.swift` | URL validation and asynchronous NetFS mount/cancel; system authentication; returns mounted file URLs. |
| `SearchRequest.swift` | Codable current-folder/Home scope, name/content/type/date conditions, native Spotlight predicates, and the app-wide SavedSearchStore of named requests. |
| `SearchBackend.swift` | Injectable search backend; off-main local traversal, main-run-loop NSMetadataQuery ownership and off-main result hydration, cancellation and bounded batches. |
| `SearchSession.swift` | Pane-owned request/results/status, generation guards, cancellation, replacement and clear. |
| `KeyboardShortcuts.swift` | Stable command catalog generated from main-menu definitions plus file-view/window alternatives; `ShortcutStore` validates syntax/system/menu conflicts, migrates the legacy Filter binding, separates cleared bindings from defaults and posts `.tursoraShortcutsChanged`. |
| `CommandPalette.swift` | Pure command-palette model: `FuzzyMatcher.match(_:in:)` (subsequence DP scoring prefix/word-boundary/consecutive hits, returning the score and matched offsets), `PaletteEntry` (command / favourite / recent) and `CommandPalette.entries(actions:bindings:favourites:recentFolders:excluding:)` / `filter(_:query:)` sorted by score, category, title, id. No AppKit, window or filesystem state. |
| `ShortcutKeyboardLayout.swift` | Resolves current-input-source Shift equivalence for shortcut conflicts and dispatch without rewriting stored glyphs; injected US/German/French layouts keep command behavior testable without changing the user input source. |
| `TerminalPreferences.swift` | Codable application-wide shell/font/theme configuration and the two folder-sync directions (`terminalFollowsBrowser`, `browserFollowsShell`, both default true) at `terminalPreferences.v1`; decoded field by field so a configuration stored before the directions existed keeps the user's shell and appearance instead of resetting. Validates executable paths separately at save and launch, bounds installed monospaced fonts and custom RGB colors, posts `.tursoraTerminalPreferencesChanged`. |
| `TerminalActivity.swift` | Read-only libproc/getsid process snapshots for the owned PTY session and descendants; classifies foreground/background/stopped work and unknown metadata. PID plus birth time is rechecked before signals, SwiftTerm termination and waitpid; shutdown signals only owned identities and shares an asynchronous completion barrier through shell reaping. `TerminalProcessLifecycle.whenAllStopped` also covers cleanup from recently closed windows. Shell-only builtins cannot be distinguished reliably from idle shells. |
| `FolderTreeModel.swift` | Lazy folder-only tree over injected `FileProvider`, with one-level background loads, generation-checked delivery, bounded ancestor reveal, root selection, hidden-folder policy, off-main `realpath` reveal of `/tmp`/`/var` aliases with the required `/private` ancestor, active-only watcher and debounced `DirectoryChanges` refresh. No file mutations. |
| `TabStripLayout.swift` | Pure tab/document/viewport geometry with a 120 pt readable minimum and overflow detection. A tab settles at a 240 pt preferred width, yielding to a title that needs more room up to 480 pt and bounded by an equal share of the strip; New Tab follows the tabs when they leave the strip part-empty, and returns to the trailing edge once they fill it (D79). |
| `TabTitle.swift` | A tab's name as two halves rather than one punctuated string, so the strip can draw a real rule between a split tab's two folder names; `plain` joins them for the Rename Tab sheet and the All Tabs menu (D78). |
| `TerminalDirectorySync.swift` | Model-owned serial file I/O for an isolated 0700 directory and 0600 request file, kind-aware over `TerminalShellIntegration`. Paths are NUL-delimited data. zsh additionally gets a FIFO, a response file with generation/token acknowledgements and a filesystem dispatch source, plus a temporary `.zshenv` that restores the original ZDOTDIR/startup path; its ZLE consumes requests at an empty primary prompt and precmd handles deferred navigation without PTY keystrokes or signals. bash (`--rcfile`) and fish (`--init-command`) have no wakeup and no response channel: they apply at the next prompt and acknowledge by reporting over OSC 7. `shellArguments` carries the interactive arguments each shell needs. Other shells retain manual restart. |
| `TerminalShellIntegration.swift` | Shell-kind detection by executable name (zsh/bash/fish) and the generated shell-side scripts for both sync directions. zsh gets an OSC 7 reporter for its precmd hook; bash a temporary rcfile that replays `/etc/profile` and the first readable login startup file before appending — never replacing — `PROMPT_COMMAND`, preserving `$?`; fish an `--init-command` with an `--on-variable PWD` reporter and a `fish_prompt` consumer. Only generated channel paths and a hex token enter executable shell text; requested paths are read as NUL-delimited data. No `eval`, `trap` or signals. |
| `FolderSizes.swift` | Per-`DirectoryModel` folder item counts and optional recursive byte sizes. Main-thread state, one serial background queue, generation + token cancellation, cache keyed by (path, modification date), invalidated through `DirectoryChanges`. Refuses recursive walks for archive entries and search results. |
| `DragAndDrop.swift` | The drag behaviours beside the drop rule: `sourceMask(readOnly:local:)` (`.generic` included so a ⌘-drag narrows to something), `validationOperation(...)` (report a ⌘-drag's move back as `.generic`, inside the mask AppKit narrowed to), `canSpringLoad(...)` and `springLoadingOptions(...)` (a target springs open only where a drop would be accepted), plus read-only access to the system's `com.apple.springing.enabled` / `.delay`. |
| `TrashLocation.swift` | Where the Trash is: `userTrash(create:)` / `volumeTrash(containing:)` over `FileManager`'s `.trashDirectory`, `knownRoots()`, pure `isTrashDirectory` / `trashRoot(containing:)` / `isInTrash`, `topLevelItems(in:)`, `isPermissionDenied` (EPERM/EACCES, `NSFileReadNoPermissionError`, wrapped underlying errors), `privacySettingsURL` and Finder's wording. `canonicalPath` uses `realpath(3)` on the deepest existing ancestor, because `resolvingSymlinksInPath()` leaves `/tmp` and `/var` alone and only rewrites components that exist. `userTrashOverride` is the injection point so checks never write into the real `~/.Trash`. |
| `TrashOrigins.swift` | The put-back journal: JSON at `Application Support/Tursora/TrashOrigins.json` (injectable, temp under smoke), serial queue + atomic writes, unreadable/foreign files retained on read. `record`, `origin(ofTrashed:)`, `forget`, `forgetAll(under:)`, `pruneMissing(under:)`, 5000-entry cap, and the pure `putBack(origin:parentExists:destinationOccupied:)` → `.available` / `.unknownOrigin` / `.missingParent` / `.nameTaken`, each refusal carrying its tooltip. `.DS_Store` is never read. |
| `DockMenuCommand.swift` | `DockMenuCommand` and `DockMenuDirectories`: the fixed Dock destinations (New Window, Downloads, Applications) as data, independent of menu construction. |

## 3. Data flow walkthroughs

**(a) Navigate to a folder.**
A new pane defers initial navigation until its owner has installed callbacks. That callback runs only while `navigationGeneration == 0`; an explicit navigation made first wins and cannot be replaced by the initial location.

1. `BrowserViewController.navigate(to:)` → `saveViewState()` (`history.recordViewState`) → `history.push(url)` → `load(url)`.
2. `load` captures the canonical `viewPropertiesKey`, sets `currentURL`, and restores applicable view properties before listing. A changed key at the same URL is a retargeted symlink: clear the prior history selection/scroll and pending selection, and treat it as a directory change for filtering and pending renames. Then clear the error, cancel `refreshDebounce`, create a `DirectoryWatcher` for ordinary directories (none for archive snapshots), call `model.load(url) { restoreViewState() }`, `onLocationChanged?(url)`, and post `.tursoraSelectionChanged`.
3. `DirectoryModel.load` lists off-main, merges, bumps `generation`, `resort()` → `Grouping.split` → `onChange`.
4. `onChange` → `fileView.reloadData()` + `updateStatus()` + `persistViewProperties()`. The last-applied value and restoration flag suppress writes for unchanged listings and restored values.
5. The completion runs `restoreViewState()` (pending selection, else the history entry's `selectedName`/`scrollOffset`).
6. The browser updates its own `addressBar.url`; `onLocationChanged` → `TabPage.onPaneLocationChanged` → `TabsController.refreshChrome()` updates both sides of the tab title and tooltip. For the active pane of the current tab, `onCurrentLocationChanged` → `MainWindowController.locationChanged` → hidden window title and `representedURL` (empty subtitle), `sidebar.syncSelection(to:)`, terminal Start/Restart destination and retained zsh directory-sync request, `validateNavigation()`, `syncFilterUI()`.

**Tab context and window ownership.** New Tab uses the clicked page's active logical location and starts a fresh single-pane browser; a search restarts its captured `SearchRequest`. Detach creates a new window from one or two logical locations, preserving physical order, active side, custom name and each search request, then closes the source tab. It does not transfer browser instances, histories, selection, filters, scroll positions, transfer tasks or undo managers. Original tasks remain owned by their original window; closing that window still cancels them and waits for cleanup. Reopen Closed Tab retains the existing full-page behavior, including its custom name. These are intentionally different state boundaries; see [the pinned Dolphin comparison](research/pane-paths-and-tab-actions.md).

**Archive navigation.** Before pushing history, `navigate(to:)` normalizes to the logical URL, prepares a ZIP if needed, and verifies that the requested location is a directory. `ArchiveFileProvider` lists its private snapshot while preserving logical entry URLs, so the existing model and both views handle arrangement and filtering. Back / Forward retain these logical entries; Up from the ZIP root selects the ZIP in its ordinary parent. Prepared sessions remain navigable after ZIP browsing is disabled. Archive destinations reject writes; copy-out, Quick Look and Share receive validated readable URLs. There is no separate archive window. `ArchiveNavigationNotice` shows a named opening state with cancellation and a recoverable failed target. Reload retries failed archive navigation, including startup with no previous directory. Navigation/closure cancels the pane’s subscription; closed tabs resume their pending target when reopened. The last subscriber cancels the worker, while prepared sessions remain retained for external readers. Worker identity prevents late completion from replacing a new attempt. Quit captures the workspace once, then waits for transfers and archive workers to finish cleanup before replying to AppKit.

Archive ownership matches aliases of the source ZIP’s parent directory while retaining lexical member components. The existing snapshot containment validator still rejects escaped member links. Before the first directory load completes, `chromeLocationURL` supplies the requested logical location for tab/window titles only; file actions continue to use `currentURL`.

**(b) Move by drag, with undo.**
1. `FileListViewController.acceptDrop` (or the grid / sidebar / tab bar) computes `dropOperation(for:into:sourceMask:)` and calls `onDropFiles`.
2. → `BrowserViewController.dropFiles(_:to:op:)` → private `transfer(...)`: captures the originating undo manager, registers a task, and calls `FileOperations.transfer` with an asynchronous task-row conflict handler.
3. Completion on main: `endBusy()`, register the successful `TransferJournal` on the captured undo manager inside `registerUndo`. Journal replay immediately registers its inverse for redo.
4. If this pane is searching, `reloadSelectingURLs` reruns its query and selects matching created URLs. Otherwise select exact created URLs when the destination is this pane, or `reload()` the current ordinary directory.
5. `DirectoryChanges.post(DirectoryChanges.affected(sources:destination:))` → every other pane and Info window observing `.tursoraDirectoriesChanged` refreshes.
6. The task row displays exact failures and a completed/cancelled/partial/failed state; smoke also prints the errors.

**(c) Outside change.** While searching, affected paths are checked against the query’s effective root; refresh reruns the query and preserves its filter and exact-URL selection. Search handling precedes ordinary directory-key retarget checks, so a retained source URL cannot turn a result refresh into directory navigation. For ordinary directories: FSEvents → `DirectoryWatcher` handler on main → `BrowserViewController.fileSystemChanged(paths)` → `isDisplaying(path)` (symlinks resolved on both sides; matches `displayedDirectories` = current URL + `fileList.expandedFolderURLs`) → `scheduleRefresh(after: 0.15)` (debounced) → `refreshPreservingSelection()`: compare the currently resolved key with the captured navigation key; if retargeted, reenter through `load`. Otherwise capture selected URLs (mapped through `pendingRenames`) and `scrollOffset`, `model.reload`, reselect URLs and restore the offset. Explicit `reload()` performs the same key check. The in-app path is identical from `scheduleRefresh` on, entered via `directoriesChanged(_:)`.

**(d) Selection → status bar / Quick Look / Inspector.** View selection change → `FileViewing.onSelectionChanged` → browser closure: `updateStatus()`, post `.tursoraSelectionChanged` with `object: self`, `panel.reloadData()` if a visible `QLPreviewPanel` exists. The Inspector observes the notification, checks the poster is the active pane of the main (or key, or only) `MainWindowController`, then `sync(with:)` → `urls = selection` (or the folder when empty) → `scheduleRebuild()`.

**(e) Filter and groups.** Typing in the toolbar field → `controlTextDidChange` → `MainWindowController.applyFilter` → `browser.nameFilter` → `DirectoryModel.nameFilter` `didSet` → `resort()` → `arrange` → `Grouping.split` → `onChange` → `reloadData` + `updateStatus`; then `syncFilterUI()` follows the active pane in the toolbar field. Filter-only changes leave the durable property snapshot unchanged and do not save it. Groups: View ▸ Group By / toolbar Group menu → `groupBy` or `toggleGroups` → `setGroupKey` → `model.groupKey` `didSet` → same path; `rememberedViewProperties.lastGroupKey` and the current group are saved by the selected directory policy. The list renders `model.groups` as group rows; the grid as one section per group.

Archive panes do not expose editable Info / Inspector targets; their Quick Look source resolves logical selections to readable snapshots.

**(f) Get Info build / rebuild.** ⌘I → `MainWindowController.getInfo` → `browser.getInfo` → `InfoWindowController.show(for: infoTargets, relativeTo:)` → registry check (standardized target URLs; summary matching preserves target order) → `init` → `buildChrome()` + `rebuild()`. `rebuild()` cancels the size calculation, saves any comment, empties the stack, adds header + `general`, `moreInfo`, `name`, `comments`, `openWith` (files only), `preview`, `sharing`, records `fileIDs`, starts the size calculation, watches the parent, fits the window. Rebuilds are deferred while `isEditing` and resumed from `controlTextDidEndEditing`/`textDidEndEditing`. Renames: in-app ones arrive as `.tursoraDirectoriesChanged` with `renamedFrom`/`renamedTo` → `follow(from:to:)` rewrites `urls` and every per-section URL; outside renames arrive via FSEvents → `parentsChanged()` → for missing items `FileInfo.sibling(of:withFileID:)` finds the same inode → `follow`. A truly deleted item closes the window (the Inspector re-syncs instead).

## 4. Cross-cutting conventions

**Callbacks vs notifications.** Parent/child links are closures (`on…`); anything that crosses panes, tabs or windows is a notification.

**View-mode toolbar sync.** After a pane mounts its new file view, `BrowserHost.viewModeDidChange(in:)` asks the window to validate toolbar state. A new pane chooses its mounted file view from the persisted mode before `loadView`, so the stored mode and actual child cannot diverge. The window ignores background panes; tab/pane activation continues to refresh through `locationChanged`. `validateNavigation` also synchronizes the Split View toggle state and its Close Left/Right Pane action title; toolbar clicks, overflow commands and the existing shortcut all call `tabs.toggleSplit` through the window.

**Restored list layout.** Apply the final model arrangement before mounting a restored view, avoiding a transient reload of old groups that scrolls a narrow inactive list horizontally. Capture the existing list clip origin and restore its horizontal position after layout; intentional horizontal scrolling stays intact.

**Directory view restoration.** A pane reads the applicable value from its injected `DirectoryViewPropertiesStore` before starting the listing, then applies mode, both remembered zoom steps, preview, grouping, hidden files and sorting under `isApplyingViewProperties`. The selected view, table sort arrow, status slider and active window chrome update through existing setters/host validation. Restoration does not save or navigate. Directory listing and archive preparation retain their existing generation guards; there is no asynchronous directory-property read whose late completion could apply A's properties to B. User changes save a full presentation snapshot to the key captured for the accepted navigation, so retargeting a symlink does not redirect subsequent edits of the old pane into the new target's record. Under per-directory policy another already-open pane stays unchanged until it reenters; last explicit edit wins for future entries. Policy changes restore all ordinary panes; default changes restore unified panes and those without overrides; resets restore matching directory panes. Filters, selection, scroll and history remain pane-local. ZIP logical locations and archive backing paths have no persistent key; each archive navigation starts from the current defaults, including navigation to another internal folder, and subsequent changes remain transient. Global policy/default/reset notifications leave already-open ZIP and search views alone. Search retains its originating `currentURL`/`viewPropertiesKey` and inherits the pane’s current presentation; `canPersistViewProperties` rejects `isSearching` and `model.isSearchResults` for saves, observers, commands and menu validation. Returning to a directory restores its current stored value; search edits never become folder overrides or unified defaults.

**Responder chain.** `MainMenu` uses `nil` targets. Window-scope actions live on `MainWindowController` — navigation (`goBack/goForward/goUp/goHome`, `reload`, `editLocation`), tabs (`newTab`, `closeTab`, `reopenClosedTab`, `nextTab`, `previousTab`), split (`toggleSplit`, `focusOtherPane`), sort (`sortBy`, `toggleSortOrder`), `focusFilter`, `toggleHiddenFiles`, `newFolder`, `getInfo`/`getSummaryInfo`/`showInspector` — because they must work whichever pane or chrome view has focus; most forward to `browser`. Selection- and view-scoped actions live on `BrowserViewController` — `copy/cut/paste`, `duplicate`, `moveToTrash`, `deletePermanently`, `renameSelection`, `quickLook`, `viewAsIcons/viewAsList`, `zoomIn/zoomOut/zoomActualSize`, `togglePreviews`, `toggleGroups`, `groupBy`, `copyToOtherPane`/`moveToOtherPane` — so they reach the **focused** pane. Both implement `NSMenuItemValidation`.

**Undo grouping.** `registerUndo(on:actionName:_:)` closes any stale automatic group, opens one explicit group, registers the body on the pane, names it, closes it, then closes the event group again — each operation is a self-contained undo group. Undo handlers re-register their inverse (move ⇄ move, copy → trash, rename → rename) and re-post `DirectoryChanges`. The Info window registers its rename on its own `window.undoManager` (D13).

**Error reporting.** `BrowserViewController.report(_:context:)` and `InfoWindowController.report(_:)` print to stdout when `SmokeTest.isRequested` (a modal would hang a headless run), otherwise `presentError`/`NSAlert`. `FileOperations.report` and sidebar Eject errors also suppress modal UI in smoke mode. Settings and server errors appear inline; archive navigation errors use the browser's inline error area.

**Finder-semantics helpers.** `FileOperations.dropOperation(for:into:sourceMask:)` (⌥ = copy, same volume = move, cross-volume = copy, own folder = no-op) is the one drop rule, used by list, grid, sidebar and tab bar. `FileOperations.uniqueURL` ("Report 2.pdf") and `duplicateURL` ("Report copy.pdf"). `TransferTasksWindowController.resolveConflict` presents transfer conflicts. `clickedItems` (selection if the clicked row is in it, else the clicked row) is the context-menu target rule.

**Workspace lifecycle.** `AppDelegate` compares complete snapshots and debounces changed state for 0.4 seconds on the main queue. Capture includes current and background tab navigation, executed queries, tab/pane mutations, divider/sidebar changes, window movement/resizing/minimization and active window changes. Startup and termination suppress incidental callbacks. The final quit save runs after terminal-task confirmation and before cleanup; cancellation leaves normal workspace saving active. It does not race an older background writer: the store's small writes are synchronous. Restoring a pane explicitly navigates before rerunning its search; its desired logical URL survives deferred initial navigation and asynchronous ZIP preparation. Folder-tree visibility, height ratio and hidden/Home-limit options are serialized with backward-compatible defaults; expansion nodes reload from the active path. History, closed tabs, filters, selection, scroll, terminal sessions, transfers and undo are not serialized.

The store bounds reading to 2 MiB, 16 windows, 32 tabs per window and two panes per tab. Malformed children are skipped with selected-index remapping; unknown document versions and wholly unusable files remain untouched. Saving an oversized live workspace reports an error instead of silently truncating it. The app preserves an unreadable source even after ordinary navigation or quit, until explicit Retry Saving Workspace or an off/on preference transition permits replacement. Disabling restoration cancels pending saves and clears only the owned session file; clear failures remain visible and retryable. Missing directories and detached volumes survive URL normalization and reach the ordinary inline navigation error without initiating server mounts. See [workspace sessions](research/workspace-sessions.md) for current verification.

The directory-view library is application-owned and shared by debug and packaged launches; it never writes into browsed folders or modifies their metadata. `directoryKey` strips query/fragment and trailing directory hints, standardizes a local absolute file path and resolves symlinks; non-file, non-local-host and virtual locations return nil. No case folding, inode, bookmark or volume-ID tracking is used. Finder alias files are not automatically resolved by browser navigation; no alias-following behavior is added by this store. If a caller supplies the resolved target directory, it naturally uses that target's key. Moves and renames use an existing record for the new path, or defaults when none exists; reused paths/mount points can inherit prior records. `properties(forKey: nil)` always returns defaults, and unified policy ignores but preserves directory records. Reset removes a record so future default changes apply.

The JSON decoder repairs invalid/missing presentation fields independently, clamps zoom indexes, and skips malformed directory entries. Missing/corrupt/unsupported-version documents use supplied initial defaults; loading or flushing without a mutation preserves their original bytes. The first effective mutation replaces them with v1. A serial queue owns memory and disk state; synchronous getters see mutations immediately, writes coalesce for 150 ms, and atomic file replacement cannot be overtaken by an older queued snapshot. `flush()` is a termination/restart barrier and retains dirty state on failure; `lastWriteError` and asynchronous `writeStatus` notifications drive a nonmodal Settings error and Retry Saving View Settings action. Canonical keys are captured per accepted navigation; refresh/reload detects retargeted symlinks and clears the prior identity’s transient state. Smoke mode uses factory defaults and a unique temporary shared-library path, never the user's Application Support library.

## 5. Threading

Off the main thread: the **root directory listing** (`DirectoryModel.load` on `.global(qos: .userInitiated)`, result delivered to main and dropped if `loadToken` moved on); **copy/move/duplicate** (`FileOperations.transfer` owns an independent worker; asynchronous conflict requests go to main while the worker waits cancellably; completion is on main); **size calculation** (`FileInfo.computeSize`, throttled `update` on main every ~0.25 s plus a final call, cancellable); **thumbnails** (bounded text reads / CoreText rasterization and `QLThumbnailGenerator`, cache write and coalesced callbacks on main). On the main thread: subfolder listings (`loadChildren`), `trash`/`rename`/`delete`, all `FileInfo` flag/comment/permission writes, and the FSEvents callback. Bursts are coalesced by `scheduleRefresh` (0.15 s) and `InfoWindowController.scheduleRebuild` (0.15 s).

Archive work runs off-main and delivers completion on main; ZIP preparation is coalesced by `ArchiveWorkspace`, with a browser navigation-generation guard against stale navigation; ordinary directory load tokens still discard stale listings. NetFS async completion is scheduled on main. SwiftTerm manages PTY I/O; explicit terminal shutdown signals only the owned session and reaps its child off-main. No shell receives injected PTY keystrokes. A retained zsh session consumes model-owned directory requests through ZLE at an empty primary prompt or a later precmd; other shells retain manual restart. Serial request/response I/O and channel/view identity guards reject obsolete acknowledgements after replacement or shutdown. Folder-tree enumeration uses `FileProvider` off-main one directory at a time; generations reject stale results after location/root/visibility changes. Refresh observes only active loaded branches and does not recursively pre-scan descendants.

Directory view storage serializes mutations and coalesced writes on its utility queue. Store notifications are posted after releasing that queue so observers can query it without recursive synchronization; AppKit observers deliver on main. Pane restoration and toolbar updates remain on main.

### Transfer tasks

`BrowserViewController` captures source URLs, destination, originating window/undo manager, and pane before starting a transfer. `TransferTask` normalizes duplicates and overlapping sources through `FileOperations.mutationSources`: an actual selected directory covers a descendant only through actual directory ancestors, so a selected symlink or an intervening symlink does not swallow an explicit `link/child` source. The engine receives the retained source identities without resolving them into targets. Paste, drag/drop (including the other pane, sidebar and tab routes), Duplicate and ZIP copy-out reach the same engine. Duplicate uses each selected source's own parent even when an expanded-list selection spans folders. Clipboard completion only clears the generation it consumed.

`TransferTasksWindowController` owns active tasks and originating windows, and polls synchronized snapshots at 10 Hz on main. Each row presents byte totals, active-time rate/ETA, phase, exact failures, and independent pause/resume/cancel controls. Conflict choices are asynchronous and scoped to the task, so waiting cannot block other tasks. The Window menu reopens hidden controls. Closing a browser window first confirms active/unknown terminal work, then cancels its transfers and delays close until owned process cleanup; closing a tab does not orphan the task. App quit performs the terminal confirmation across all windows before starting any termination cleanup, then uses `terminateLater` until transfer workers and owned PTYs are reaped. `applicationWillTerminate` flushes the directory-view store and releases Info, undo-journal and archive resources. The [terminal lifecycle record](research/terminal-session-lifecycle.md) separates process-detection limits and pending verification from completed historical checks.

The footer has no terminal status control, activity polling or elapsed timer. Restart, window close and quit take fresh action-time activity snapshots; global cleanup still covers recently closed windows. `TerminalDirectorySync` remains independent of presentation: hidden sessions retain their private channel, while replacement, shutdown and process exit invalidate it. A model-owned filesystem dispatch source observes acknowledgement writes in the private channel directory and is cancelled during cleanup; it does not poll process activity or launch a PTY. See [the 0.2.1 record](research/terminal-navigation-0.2.1.md) for navigation and input-preservation boundaries.

The engine scans with unknown totals first, copies file data in bounded blocks, applies native metadata, then exclusively publishes a complete item. Same-volume moves capture only their root identity, use atomic renames without enumerating opaque descendants, and contribute no fabricated byte transfer. Native metadata/fsync and the short commit transaction are explicit finishing phases without an ETA. Cross-volume source retirement occurs only with complete destination publication, in the same rollback-capable commit. Journal replay uses retained same-volume names, preserving replaced destinations and merged children while registering its inverse synchronously with `NSUndoManager`. Recovery storage normally remains while undo/redo history retains its journal. A failed replay retains its recovery directories independently of UndoManager history and reports their paths for manual recovery; it consumes disk space and is not an automatic session-recovery feature.

`TransferSmokeTests` runs before existing archive/UI checks, testing deterministic block pause/cancel/faults, metadata/symlinks, conflict policies, concurrent tasks, cross-volume boundaries and actual list/icon UI routing, captured context, undo/redo and lifecycle. Validation evidence lives in `docs/research/file-operation-tasks.md`.

## Native archive and server services

`ArchiveOperations.swift` extends `FileOperations` with asynchronous ZIP creation/extraction, private staging, exclusive publication, system metadata and quarantine handling. `BrowserViewController` captures inputs, tracks busy state, registers output undo, and posts directory changes. `ArchiveSmokeTests` covers isolated model operations and malicious fixtures; `SmokeTest.archiveUI` covers both views, menus, grouping/filtering, splits and undo/redo.

`ArchiveWorkspace` retains read-only snapshots until application shutdown, including after tabs or windows close. External applications can keep using opened copies, but no operation writes their edits back into the source ZIP. The logical path is an application location, not a new on-disk directory or registered URL protocol. Full extraction requires temporary disk space; changing the source ZIP does not automatically refresh its snapshot. See [archive browsing research](research/archive-browsing.md) for current verification boundaries.

`ServerConnection` implements `ServerMounting` through NetFS async mount/cancel. `ServerConnectionController` owns address validation and inline state; the system owns authentication. Success returns local file URLs. `PlacesModel` observes workspace mount notifications and classifies network volumes. `ServerConnectionSmokeTests` uses a mock mount service and never contacts a server.

## Application icon export

`app/Resources/AppIcon-artwork.png` retains the original square two-pane tail-fin artwork. `app/tools/render-icon.swift` draws it at the same canvas-relative scale and position into a cleared 1024 × 1024 CoreGraphics bitmap, clipped to a rounded rectangle at `(80, 80)` with size `864 × 864` and corner radii `192`. ## Software update service and release feed

The production driver uses Sparkle's main-thread APIs and KVO for scheduling, user defaults, download/install UI and relaunch. Initial defaults live in `Info.plist`: automatic checks on, automatic downloads off, optional system profile off, and signature verification before extraction on. Sparkle's default interval is one day. The app does not set these preferences at startup or keep duplicate keys in `AppPreferences`. Turning off automatic checks disables automatic-download eligibility; the stored download choice survives and takes effect again when checks resume. Existing downloaded or deferred-install updates follow Sparkle's lifecycle.

`make-app.sh` copies the complete `Sparkle.framework` to `Contents/Frameworks` with `ditto`, preserving symlinks, executability, signed helpers and XPC services. The executable has an `@executable_path/../Frameworks` runtime search path; packaging removes SwiftPM's development-directory paths before signing. The script signs only the outer app with its existing ad-hoc signature, then validates the fixed feed URL, public key, defaults, runtime paths and embedded components through `update-metadata.py`. It does not re-sign nested helpers with `--deep`.

`make-dmg.sh` converts the complete app into a compressed HFS+ DMG with a Tursora-to-Applications arrow layout. `dmg-settings.py` writes a 640 × 280 icon window, 128 px icons at `(140, 120)` and `(500, 120)`, and the `/Applications` symlink. The background license lives at the volume root so the signed app remains unchanged. Python 3.10+ runs the hash-pinned wheels from `dmg-requirements.txt` in `.build/dmg-tools`; CI sets up Python 3.13. The script mounts the image read-only and validates the app and saved layout without controlling Finder.

Stable releases include the DMG directly and `appcast.xml` as release assets. `SUFeedURL` points to `https://github.com/zerolfx/Tursora/releases/latest/download/appcast.xml`; each feed contains one current stable item with embedded notes, an immutable versioned DMG URL, minimum macOS and arm64 requirements, size and Ed25519 image signature. `make-appcast.sh` invokes Sparkle's tools, passes signing material through stdin, verifies the output metadata and image signature, and copies the feed into release assets. The XML itself is not signed (`SURequireSignedFeed` is unset). No delta updates or prerelease channel are generated. The historical 0.1.0 ZIP asset is not rewritten.

`CFBundleVersion` defaults to the source commit's Unix committer timestamp, avoiding unrelated Build/Release workflow run-number sequences. Stable publication rejects a non-increasing semantic version and, when the previous release has an appcast, a non-increasing build. Public key material is versioned in `app/Resources/SparklePublicKey.txt`; private material belongs in the maintainer's Keychain and the repository's `SPARKLE_PRIVATE_KEY` Actions secret. Configuration and actual release status are recorded separately in [the update research](research/app-updates.md) and [release instructions](RELEASING.md).

## Search ownership and lifecycle

`SearchRequest` contains Codable scope and AND conditions; `SearchSession` accepts an injectable `SearchBackend` and rejects callbacks after its generation changes. `LocalSearchBackend` traverses ordinary folders off-main for filename/type/date requests, reads candidates through `ContentScanner` when a content request asks to scan (D85), and uses an owned NSMetadataQuery on the main run loop for text-content requests. Item hydration happens off-main. `SavedSearchStore` persists only named requests in UserDefaults.

`BrowserSearch.swift` wires each browser's `SearchPanelController` and session to `DirectoryModel.beginSearchResults/replaceSearchResults`. The result container has `DirectoryModel.url == nil` while each `FileItem.url` remains its real source URL, so they cannot become an implicit paste/drop destination; `isSearchResults` also disables unfiltered tree expansion. The browser retains the originating ordinary directory and captured view-properties key for navigation chrome and return restoration, not as a search destination or a writable view-properties record. Session callbacks and search reload completions run on main; navigation clears the session before directory loading. Search-specific selection preservation always uses full URLs, including view-mode changes, rename/undo, duplicate and trash.

Selection mutations use `canModifySelectedItems`; directory destination operations use `canModifyCurrentLocation`. FileOperations and window undo groups remain responsible for filesystem changes. Search Copy/Move/Duplicate use the shared TransferTask engine and normalized source set; Duplicate publishes beside each retained source. Transfer completion uses `reloadSelectingURLs`, while replay and directory notifications rerun the active query; Trash undo also restores exact URLs. No completion may select a same-named file from a different result location. Search rows display Location in the list and an extra parent label in the icon grid. The panel reads/writes saved conditions through its store and never mutates files. `SearchSmokeTests.swift` covers injectable backend lifecycle before real UI integration. `IntegratedSearchSmokeTests.swift` checks both directory-view policies, origin-directory retargeting, and parent/child transfer selection in both concrete views. It also covers source normalization and real Copy workers for a selected link plus its child and for an actual `root` plus `root/link/externalChild`; both must publish the separately selected child. A selected actual directory below a link still deduplicates its own ordinary child. These describe coverage, not completed combined verification; current results remain in [the PR integration record](research/pr-integration-2026-09-12.md).

The single toolbar search entry reads `BrowserViewController.searchFieldText`: ordinary `nameFilter` or the recursive panel draft. Non-empty ordinary filtering reveals the compact Search Options row; explicit expansion resets stale conditions for the current root and schedules a non-empty draft. `SearchPanelController` owns a generation-guarded 500 ms delay; navigation and closure cancel it, while reopening a retained tab reschedules a draft that differs from its submitted request. First search-field edits are adopted before chrome sync; empty-name blur cannot close content/type-only searches. The native cancel cell and Escape own return-to-folder behavior; programmatic chrome updates are guarded from delegate feedback. Programmatic presentation never schedules or takes editor focus.
