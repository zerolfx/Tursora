# Decision Log

In chronological order. Each entry records what was chosen, why, and what it costs. When we change our mind, the new entry is appended below the original one; nothing is deleted.

| # | Date | Decision | Rationale / cost |
|---|---|---|---|
| D0 | 2026-08-19 | **No Dolphin / KIO port; a native rewrite** | Phase 0 audit ([audit/PHASE-0-REPORT.md](audit/PHASE-0-REPORT.md)): a port is feasible, but the basic functionality comes almost for free on native macOS APIs while the KIO stack is almost pure cost; Dolphin's differentiation lies in its UI behaviour. The audit is not void — the APFS case handling, NFD/NFC, `UF_HIDDEN` and per-volume `.Trashes` issues it records will be hit on the native route just the same |
| D1 | 2026-09-10 | The tab bar is **custom-drawn**, not `NSWindow.tabbingMode` | Native window tabs hard-wire "one window per tab", which fights with split panes; they also cannot produce Dolphin-style compact tabs. Cost: tab dragging, reordering and close buttons all have to be drawn by hand |
| D2 | 2026-09-10 | v1 views = list (`NSOutlineView`, expandable in place) + icons (`NSCollectionView`), with zoom and preview | The icon view was originally planned for v2; the user asked for it earlier. Compact view is not being built |
| D3 | 2026-09-10 | `Return` = rename (Finder), `⌘↓` = open; clicking the text of an already-selected item enters rename after a delay | Follows the muscle memory of macOS users, not Dolphin. The decision does not depend on the ordering of `mouseDown` and the drag-session callbacks |
| D4 | 2026-09-10 → 2026-09-11 | App name **Tursora**, bundle id `com.tursora.Tursora` (the packaging script's `TURSORA_BUNDLE_ID` can override it) | Originally Otter File Manager / `com.otterfm.Otter`, renamed on 2026-09-11. Cost: the release build's UserDefaults domain follows the bundle id, so old favourites and preferences are not migrated |
| D5 | 2026-09-11 | Split panes moved up to v1, structured like Dolphin (tab → 1–2 panes), not "several tabs per pane" | The user confirmed that we follow Dolphin |
| D6 | 2026-09-10 | **No Xcode**: SPM plus a packaging script produces the `.app`; no nib / storyboard / asset catalog | The Command Line Tools are enough. Cost: every piece of UI is built in code, and icons can only be SF Symbols and system icons |
| D7 | 2026-09-10 | `swift-tools-version:5.9`, Swift 5 language mode | Avoids the rework cost of Swift 6 strict concurrency; AppKit code is full of main-thread callbacks |

| D9 | 2026-09-11 | Shortcuts: `⌘1…9` = tabs (Dolphin), view modes on `⌘⌥1/2`; `⌘L` = edit the location | This conflicts with Finder's `⌘1–4` views and its `⌘L` make alias; accepted. Aligning them is left as a follow-up item ([gaps/GAP-vs-FINDER.md](gaps/GAP-vs-FINDER.md)) |
| D10 | 2026-09-11 | File-operation semantics follow Finder: drag and drop pops up no menu (move within a volume / copy across volumes / `⌥` copies); the conflict dialog follows Finder's Keep Both / Skip / Stop / Replace plus Apply to all | Dolphin's "menu on drop" and its "skip all / overwrite / auto-rename" are both reshaped into the forms macOS users know |
| D11 | 2026-09-11 | Filtering: the shape follows Finder (toolbar search field plus scope bar), the semantics follow Dolphin (substring plus wildcards, per pane) | Half from each side; see SPEC §8 |
| D12 | 2026-09-11 | **Finder evidence rule**: any label, wording, icon or group name that claims to "match Finder" is based only on Finder's own resources (`strings` to extract the nibs, `plutil` to read the string tables); anything inferred must be marked "still inferred" in the docs | Remembered Finder details are often wrong (group names, group order). Cost: after nib deduplication we cannot get the icon name of every individual item |
| D13 | 2026-09-11 | Undo is per window; no Finder-style global undo stack | `NSWindow.undoManager` is there already; a rename done in an Info window registers on the Info window's own stack |
| D14 | 2026-09-11 | An Info window never becomes the main window | Otherwise the Inspector and the Go menu would follow the Info window. Done with a `canBecomeMain = false` subclass |
| D15 | 2026-09-11 | Reading file flags (locked, hidden extension, readable/writable) goes through `FileManager`, not `URL.resourceValues` | The latter caches within a single run loop pass, so a read straight after a write returns the old value |
| D16 | 2026-09-11 | Folders always sort before files, and this cannot be turned off | Finder / Dolphin default; making it a preference is left as a follow-up |
| D17 | 2026-09-11 | Background agents are used only to read code and produce docs, and to do one adversarial review of a diff; things like difficulty estimation are no longer run massively in parallel | User feedback: 97 agents was excessive and hit the quota |
| D18 | 2026-09-12 | The smoke test waits at startup for the first directory load to finish, up to 15 seconds | A fixed one-second wait treats an asynchronous load that has not finished as an empty directory; waiting by generation ends the wait for empty directories and errors too, and a timeout fails explicitly. Cost: a stuck load is waited on for up to 15 seconds; we do not promise that a cold-start directory can be listed within one second |
| D19 | 2026-09-12 | Remove D11's passive scope bar, keep the name filter field and the status-bar count; real recursive search is planned separately | Dolphin clearly separates filtering from search; with only the current directory as a scope, the disabled folder button manufactured a choice that does not exist. Regular expressions, a case switch and a search backend are not added for now |
| D20 | 2026-09-12 | A uniform corner radius on the outer window, with a flat seam between sidebar and content; a custom sidebar button pinned at the left end, and the duplicate title hidden | Avoids the button migration and the inconsistent seam caused by the system sidebar's own split; the cost is giving up the system sidebar's automatic overlay layout, keeping manual resizing |
| D21 | 2026-09-12 | Tags and Import from iPhone are explicitly not being built; the existing Tags group and the tag reading are deleted | Product scope defined by the user, not counted as a gap to close. A file's existing tags are preserved: we neither write nor delete tag metadata |
| D22 | 2026-09-12 | More-actions reuse the Browser file operations; sharing uses the system picker | Menus always validate against the selection of the active pane, and file operations keep undo and refresh; the system decides which share services are available, and the app never sends files itself |
| D23 | 2026-09-12 | CI build artifacts are kept separate from manual Releases | An ordinary push / PR only produces a snapshot; a Release is triggered manually on main only, creates a new tag for an exact SHA, and refuses to overwrite an old tag. The artifact is currently Apple Silicon, ad-hoc signed |
| D24 | 2026-09-12 | ZIP is handled through the system ditto / libarchive in an isolated working directory, and published by an exclusive rename once finished | Avoids overwrites, partial output and path escapes; preserves macOS metadata and the quarantine flag. The cost is that compression copies the input first and needs extra disk space; this round supports neither passwords nor other formats |
| D25 | 2026-09-12 | Remote storage goes through system NetFS mounts; the browser continues to handle only file URLs | The user asked for Finder-style Connect to Server and mounted volumes; the system handles credentials and protocols, and the app reuses the local views and operations. There is no home-grown SFTP/KIO backend; a real server still needs on-site verification |
| D26 | 2026-09-12 | Add app-level settings; expose only extension display, the name-filter shortcut and two experimental switches | The user asked for configurability; the filter shortcut is checked against existing command conflicts, and the extension setting only changes display — renaming uses the real name. Other Finder / Dolphin preferences are still not implemented |
| D27 | 2026-09-12 | The terminal uses a pinned SwiftTerm 1.15.0 plus a PTY, off by default; navigation only updates the target of a manual Restart | Real interactive programs need terminal emulation. Injecting a cd into an existing session could land inside a running command or a shell read, so we do not sync automatically; the cost is that changing directory requires an explicit restart, and closing the panel ends the session |
| D28 | 2026-09-12 | ZIP browsing is a separate read-only window, off by default; opening a file uses a temporary copy and does not write back to the archive | Keeps the default Open = Extract and avoids applying ordinary file operations to a virtual archive by mistake. The copy is kept until the app quits so external programs can use it, and keeping changes requires Save As; the cost is that a full staging copy takes disk space and that this is not zero-extraction browsing |
| D29 | 2026-09-12 | Replaces D28's separate-window design: read-only ZIP browsing is wired into the existing pane, and navigation uses a logical URL made of the original ZIP plus the internal path, with reads mapped onto a shared temporary copy | Reuses the list / icon views, history, the location bar, filtering, tabs and split panes, so there are not two sets of browsing interactions; every write entry point is uniformly disabled, Copy / dragging out only copies, and the terminal uses the directory containing the original ZIP. The experiment is still off by default, and turning the switch off does not break an already-open archive tab; the limits of full extraction taking space and of not writing back are unchanged |
| D30 | 2026-09-12 | Per-directory memory by default; a versioned path library in the app's own Application Support, offering a uniform default, saving the current settings as the default, and restoring the current directory. An ordinary directory change is not synced live to other open panes showing the same directory, while explicit default / policy / reset actions do sync the affected panes; logical tabs such as ZIP use only the state of the current session | [Pinned Dolphin source evidence](research/directory-view-properties.md). The two view modes store their zoom separately; the default and the per-directory customisation are kept apart, and restoring does not write back. An app-owned library does not pollute user directories and does not require the directory to be writable, and it handles corruption and read-only volumes more consistently than xattr; the cost is that a record does not follow a move or a copy, and that a mount point or a reused old path may inherit a record. Paths resolve symlinks first; aliases rely on navigation to resolve them, with no inode/bookmark tracking. Serialised merging with atomic writes avoids a late write overwriting a newer one; an unknown version is preserved until an actual modification. Unlike Dolphin, switching to the uniform policy does not automatically promote the current pane to be the default. Filter / selection / scroll / history are not persisted; session restore is implemented separately in the later D48, and recursive application is still planned separately |
| D31 | 2026-09-12 | Local copy / move are unified into independent tasks that can be paused, resumed and cancelled; conflicts are decided asynchronously inside the task, and the result is published only once staging is complete | Guarantees that a single large file stays controllable and that tasks do not block one another, and that a failed Replace never deletes the old target first. The atomic move / metadata finalisation do not invent an ETA; this does not extend to network protocols or to controlling the ZIP tools |
| D32 | 2026-09-12 | Transfer undo stores a reversible filesystem rename journal plus private restore content, bound to the task's originating window; closing a browser window cancels and waits, closing a tab lets it continue, and quitting cancels all tasks | Only genuinely successful items are undone; Replace and cross-volume Move can be restored safely, and Merge does not touch unrelated content at the target. The cost is that the restore content occupies space for as long as the undo history keeps it, and that waiting for cleanup before quitting may be limited by filesystem response time |
| D33 | 2026-09-12 | Search is independent of the name filter; name / kind / date traverse in the background directly, while content uses NSMetadataQuery; saved criteria live in the app preferences, and the search view keeps only the current session's pane state | Lets an unindexed ordinary directory still be searched by name, while content reuses the macOS importers; the scope is explicitly the current folder or Home. We accept the limits of content indexing, do not search inside ZIPs, take a one-shot snapshot of the results and do not interoperate with Finder Smart Folders; results have no default write target, and file operations always use the real URL. Search inherits the pane view as it was at launch, and cannot overwrite the source directory's record or the uniform default; after it closes, the directory settings are read again. A file-operation refresh re-runs the current query |
| D34 | 2026-09-12 | The location bar belongs to each pane; split-pane titles have a fixed left/right order (the parenthetical marker originally in this entry has been superseded by D37) and allow a custom name; the tab bar is always shown and offers Dolphin's seven context-menu actions | [Pinned source and trade-offs](research/pane-paths-and-tab-actions.md).
