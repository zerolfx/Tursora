# Shortcuts, terminal, folder tree and distribution integration (2026-09-13)

This round fast-forwarded from `b58c1ce` on the public `main` and then created `codex/customization-and-distribution`. MIT was adopted at the user's explicit choice; the folder tree was implemented after checking it against Dolphin; what the toolbar gained is the terminal toggle.

Three agents took shortcuts, the dedicated terminal / tree tests, and the distribution / docs / screenshot pipeline respectively; the main task took the terminal toolbar, the folder tree and its window / session integration, the unified smoke run, and the checks on the actual packaged app. No user-facing tasks were created, no branch was pushed, no version was released and the site was not deployed.

## Fixes made during integration

- Temporary-path tests cannot assume that Foundation's `resolvingSymlinksInPath()` keeps the `/private/var` spelling; the tests use the filesystem's actual identity, and in the product the whole-tree following uses the physical ancestor resolved in the background and keeps `/private` where needed.
- The font size used to be saved on Return only; it now commits on Return / Tab / losing focus, while keeping the shell and colour drafts that have not been applied yet.
- Shortcuts do not pin `+` to US Shift–Equals; equivalence is judged from the current input source, and the saved character is not rewritten. Function keys use the SDK key code mapping, so empty characters no longer make recording F6 fail.
- During a programmatic reload / reselect, Shortcuts suppresses the selection callback of the old row so that the command target is not rewritten by the stale row; the initially selected item is scrolled into view.
- A path-locating callback is satisfied only after the tree's queued refresh has finished; an expired tree and removed loading nodes clear their callbacks to avoid reference cycles; the selected row is fully visible in the final layout, and scrolling manually to look at another branch is not dragged back by a refresh.

## Observed on a real machine

- The four-page layout in General and the entry points for the two features that are on by default; in Updates the automatic check toggle and the automatic download control move together.
- The terminal toolbar opens / collapses, and its selected state and tooltip stay in sync with the current shortcut. Environment variables are kept between commands; the font / background update live while older output is kept, and the shell choice takes effect at the next launch; an invalid shell uses an inline error.
- Recording Cmd-T was rejected as a conflict; after changing it to Control-Command-T the collapse really worked. After the fix, F6 can be recorded and really opens / collapses both from the file area and from inside the terminal.
- Entering a font size of 16 and pressing Tab updates the stepper, the preview and the saved value together; 14 was restored afterwards for the demo.
- F7 shows Folders and Places separately. In the packaged app after the fix, the selected row at the bottom is fully visible; it still follows after the divider between the two panels is dragged, a single click on Model navigates, and a right-click on UI → Open in Other Pane keeps the left pane and activates the right one.
- The installation image comes from the DMG actually produced and verified this round, mounted read-only, with the app inside the image not installed. A dedicated Finder window hid the toolbar and showed both icons in full; the same browsing window, at the same 641 × 281 geometry, switched to an empty directory for the dark reference shot and then returned to the image for the final source shot. The white background inside the installation image is original content; only the outer edge of the window was made transparent.

- AppKit's shouldExpandItem is a permission query; the old implementation would load and progressively expand other Home subdirectories when accessibility read the tree. It is now a side-effect-free query, and loading happens only on an actual didExpand; in the real screenshots and AX queries taken after the fix, the other directories stay collapsed and the Loading state ends.
- Testing on a narrow window found that the existing breadcrumb layout rebuilt the overflow button on every pass and kept toggling the visibility of the root arrow, forming a layout loop; after sampling the main thread to locate it, it was changed to stable controls updated on demand. After the fix, actually dragging from 1100 × 740 down to the minimum 560 × 380 kept the two panes, long paths and the tree responsive, with the terminal button still visible and able to open / collapse; dragging back to the original size and exiting normally both passed. Automated checks additionally cover controlled window sizes such as 560 × 360.
- Reopening the QA copy alone after switching it to the process-level light appearance restored the folder tree's shown state, the split ratio, the two panes and the two tabs, with no terminal created automatically; the light-mode list / tree and the font, colour and path controls in Terminal Settings were readable, and it then exited normally. The system appearance and the production preferences were not changed.
- Shortcuts gained regressions for Summary being displayed on its own in place of the menu after Inspector is rebound, and for Forward Delete matching its menu character and being distinguished from Backspace.
- In the isolated copy of the final `package-delivery` binary, Shortcuts recorded the terminal as ⌘⌦; after Settings was closed the real key press opened the terminal, pressing the same key again inside the terminal collapsed it, and the toolbar state and tooltip updated in step. The final window screenshots were inspected and the app then exited normally; the application list confirmed that the dedicated QA app had ended.
