# Search: semantics, backends and limits (2026-09-12)

## Evidence

Read-only cross-check against the Dolphin pin `5e457ee9e88aa6277fbf056cd5c32462c5318866` in the original workspace: the automatic search, the criteria entry point, saved criteria and Here / Everywhere in `src/search/bar.cpp`; file name / content, type, date and the backend-capability hints in `src/search/popup.cpp`. The fixed source evidence for the input, the 500 ms timer, Return and the separate Filter Bar, along with the implementation status of the unified entry point built here, is in [Search input and criteria entry point compared](search-input-reference.md). The [earlier filter comparison](dolphin-filter-search.md) is kept as a historical record. This feature does not claim to reproduce Finder's search wording verbatim, and it does not copy Dolphin's separate search bar and criteria popup as they are.

Apple's [NSMetadataQuery](https://developer.apple.com/documentation/foundation/nsmetadataquery) and the [notes on asynchronous metadata queries](https://developer.apple.com/library/archive/documentation/Carbon/Conceptual/SpotlightQuery/Concepts/QueryingMetadata.html) support URL scopes, asynchronous gather notifications and stopping a query; updates must be stopped or paused while results are accessed. Spotlight only returns what is visible in the system index, and the user's privacy exclusions and the format importers change the results. The SDK's actual declarations and the compiler are what the local API check rests on.

## Choices

- The user confirmed a single toolbar input field: by default it filters the current folder immediately; once something is typed, the owning pane's Search Options entry point appears, and expanding it searches subdirectories with the same words and offers content, scope, type and date criteria. There is no separate Search toolbar button or panel execute button any more, and no second visible name input field is added. ⇧⌘F still expands it directly from an empty input.
- Ordinary filtering keeps the `*` / `?` rules; once expanded, the name criterion becomes a literal contains match, the words carry over as they are and wildcards are no longer expanded. The placeholder and the tooltip switch with the mode. After expanding, changes to the name, the content and the criteria are coalesced into a 500 ms automatic submit, and Return submits immediately; Return in the toolbar hands focus to the result view, while an automatic submit does not steal editing focus. While an input-method composition in the name / content field is uncommitted, a pending automatic query is cancelled.
- Either a recursive search of the current folder, or the wider recursive scope explicitly labelled Home; Home does not mean the whole Mac, and it is not the same as the full set behind Dolphin's Everywhere backend.
- Without a content criterion, ordinary directories are enumerated in the background and matched with an AND of file name, UTType and modification date. The name is a case-insensitive contains match. The walk does not descend into packages, ZIPs or symlinked directories it meets; an explicitly chosen root path has its links resolved first and that real directory is searched.
- With a content criterion set to `Using: Spotlight Index`, `NSMetadataQuery`'s `kMDItemTextContent` and metadata criteria are used; no full-text index of our own is built. **Later change (2026-09-16, D85):** `Using: Scan Files` reads the candidate files during the same walk instead, bounded to 1 MB per file, 64 MB per candidate and 20,000 files, so an unindexed folder is searched. The index remains the default. No result for content the index does not cover must not be read as that content not existing on disk. The content-criterion tooltip and the content-query status explain the macOS index, the supported formats and the exclusion limits, while ordinary name filtering shows no irrelevant index explanation.
- A query is a snapshot of the results; editing a criterion re-runs it automatically, and Return or Reload can run it again. File operations applied within the results trigger a refresh through `DirectoryChanges`, still using the owning pane's submitted request and the real file URLs; after an external change, Reload is available.
- The draft, the pending-submit timer and the SearchSession all belong to the pane; the shared toolbar switches with the active pane without transferring ownership of the query. Cancelling and replacing bump a generation first, so a late callback cannot overwrite newer state. Leaving search or navigating clears the search context; closing a pane, a tab or a window cancels an automatic submit that has not been issued yet. Closing a tab keeps its pane state for reopening; on reopening, if the draft differs from the submitted request, a query is scheduled again. Navigation within the same directory that keeps the filter keeps the Search Options entry point too.
- The date lower bound is inclusive and the upper bound exclusive; Today / Last 7 Days / Last 30 Days are saved as the fixed start and end dates of that moment, and reopening still uses those bounds rather than rolling them forward. Clear empties the criteria, the results and the request while keeping the scope and the expanded panel; a completely empty input and an empty saved criterion both start no broad scan, while content / type / date on their own can still be queried. The toolbar cancel button and Escape leave search explicitly; when the name is empty, losing focus alone does not close a content or type search.
- The cap per run is 50,000: the recursive walk truncates by matched results, and Spotlight examines at most the first 50,000 indexed candidates; both prompt the user to narrow the criteria.
- A saved search is the criteria and the scope in the application preferences, not a Finder `.savedSearch` file; deleting one deletes only the criteria. Opening a saved item restores the criteria and runs them again after validation through the unified submit path; stale results are not stored.
- Search results use the real URLs; the list's Location column, the icon view's location label and the path tooltip show where an item comes from, and results with the same name are still selected separately. There is no default directory to write into, so New Folder, Paste, Compress and Extract are not offered in the result context. Open, Reveal in Enclosing Folder, Quick Look, Copy, Rename, Duplicate, Trash and cross-pane transfers use the real source; a drag into an explicit directory target still works.
- Inside a ZIP the Search entry point is disabled and the extracted temporary copy is not searched; an ordinary directory can still find the ZIP file itself. Tags, ratings, regular expressions, a full-text index of our own and interoperability with Finder Smart Folders are not implemented.

## Verification

The automation, the Spotlight path on a real machine and the packaged-app computer-use results from the earlier standalone-search stage are kept in [search-verification.md](search-verification.md). There, the native predicate's started / completed results were both zero and a real positive content hit was never verified; the entry-point change here does not alter that historical limit, and index latency is not treated as a stable precondition for the smoke test.

In the screenshot stage, before the Dock work and the later input-method changes, the full smoke test on the combined sources **passed three times in a row, 2,024 checks each**, all three with exit 0 and empty stderr; that is the total for a combined suite covering the search backend, file operations and the unified-entry-point regressions. The final results of the later Dock / input-method stage are in the [Dock research record](dock-menu.md).

`SearchEntrySmokeTests.swift` covers both views, the single input field, automatic submit and immediate execution, pane / tab drafts, an explicit cancel, losing focus with an empty name, an empty saved criterion, the same-directory hint and the draft on reopening; the existing search-backend and file-operation cases are kept.

For that screenshot stage the release build, the strict codesign, the Info.plist lint and the in-bundle icon consistency check all passed, with the build log at `/private/tmp/tursora-tabs-appearance-verification/release-final.log`. In the packaged application, under the system dark appearance and the in-process light appearance, typing `Notes` in the Delivery pane → filtering the current directory → Search Options → automatically getting one `Release Notes.md` result was actually carried out, with the Design pane unaffected; the toolbar's native `×` and Escape returning to the directory were checked. See the [current-filter image](../images/features/name-filter.png), the [dark search image](../images/features/search.png), the [light search image](../images/features/search-light.png) and the [packaged-app scope](search-input-reference.md#verification-status-for-this-round). This is name-search evidence for the 2,024-check stage bundle, not verification of the latest binary after the Dock / input-method changes, and it does not change the limit that a real positive content hit is still unverified.
