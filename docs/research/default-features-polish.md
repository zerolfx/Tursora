# Terminal and ZIP browsing on by default (2026-09-13)

> 0.2.1 has superseded the directory following and terminal bar layout described earlier in this document: zsh follows the browsed directory one way at a safe prompt, the top is reduced to a single line, and the bottom no longer shows terminal status or available capacity. For the current behaviour and that round's verification see the [0.2.1 record](terminal-navigation-0.2.1.md); the check counts, screenshots and operation records in this document stand for their own historical stage, and keeping the session when hidden and confirming before termination still apply.

> This page records the historical stage at `b58c1ce`. For later terminal settings and retention on collapse / exit confirmation see [Terminal customization](terminal-customization.md) and [Session lifecycle](terminal-session-lifecycle.md); the F4 reaping and exit ordering below reflect only what was measured at the time.

The user asked for both features to be on by default, and for first use and everyday operation to be polished further. The new code keeps the original UserDefaults keys and reads true when no record exists; an existing false is not overwritten. An explicitly set value is written to disk even when it matches the current default, but a notification is posted only when the displayed value actually changes. An older version's unwritten default of false cannot be distinguished from never having chosen, so no migration intent is guessed.

The group in General becomes Terminal & ZIP. A shell is created only when the terminal is expanded with F4; new windows, navigation, workspace restore and ticking the option itself all start no terminal. For ZIP, the default Open browses in the current pane, while an explicit Extract still extracts and supports undo. Once the option is turned off, a new Open in an ordinary directory goes back to extracting, and existing read-only pages are not broken.

## ZIP polish

While preparing, the owning pane shows Opening, the file name and Cancel. Escape cancels only while the file view has focus, and Back cancels too; leaving the directory or closing the pane / tab / window releases that view's own preparation subscription. The original directory and selection are kept on failure or cancellation, and a restore launch with no previous directory returns to the ZIP's enclosing directory after cancelling. A failure offers Retry and Open Enclosing Folder, and Reload also retries the retained logical target. Closing a tab aborts the preparation, and only reopening that tab prepares again. A launch page that has not yet established a currentURL names the tab and the window after the requested location and keeps that actual name after a failure; this display fallback does not change where file operations act.

`ArchiveWorkspace.prepare` returns a subscription; each waiter cancels independently, and the last waiter to cancel cancels the underlying preparation. Every job has its own ID, so when the same ZIP is retried immediately after a cancellation, an older completion cannot overwrite the new job. A copy that is already prepared and may be read by an external application is still kept until exit.

The extraction token is checked for cancellation at process start / exit, during quarantine attribute propagation and at the publish boundary. `cancel()` does not wait for the child process on the main thread; the worker cleans up the private directory after reaping the child, and an exit barrier waits for every in-flight job. On the first termination request AppDelegate saves the workspace synchronously, then cancels transfers and archive preparation, and replies to AppKit once cleanup finishes; the final willTerminate no longer overwrites the locations captured the first time.

Checking on a real machine turned up a restore boundary around system directory aliases: the `/private/tmp` prefix of an existing ZIP may be normalised to `/tmp` by Foundation, while a ZIP member path that does not exist on the physical filesystem keeps the original prefix. The registry now matches the canonical path of the ZIP's parent directory and then maps the snapshot by member components; it does not resolve member symlinks, and it does not treat an ordinary symlink pointing at the original ZIP as a snapshot root.

Entry enumeration skips only members that disappear after the directory listing; permission and other errors are still reported. Archives are still extracted in full, are read-only and are never written back, and no password or other format support is added.

## Terminal polish

The title is Terminal. The status line uses Started in for the launch directory; Shell folder is shown only when the current terminal instance has reported a valid local OSC 7 address. The default shell does not necessarily send OSC 7, so the launch directory must not be described as the live directory. A separate second line always shows the full visible target of Restart in / Start in (a long path is truncated and keeps its tooltip). Browsing navigation still injects no cd.

ready / running / ended / failedToStart are distinguished explicitly; a natural exit keeps the output, navigation does not overwrite the end notice, and the button becomes Start in Current Folder. Callbacks after a close, callbacks from an older terminal instance and invalid file URLs — non-local, carrying credentials and the like — are ignored. The existing session's close and PID reaping rules are kept, and terminal sessions are not restored.

## Verification

The first version, at 83 Swift sources, completed **2,557 smoke checks passing three rounds in a row**, each exit 0 with empty stderr and the source hashes identical before and after. Coverage: isolated preference defaults / an already-stored off choice, the default Open and the explicit Extract / Undo in both file views, shared-job cancellation and the stale-completion race, restore-on-launch retry for a broken ZIP, terminal header state / callback identity, and the existing PTY tests. That result predates the system path alias and launch title fixes found on a real machine. After the fixes, the final 83 Swift sources completed **2,566 smoke checks passing three rounds in a row**, all three exit 0 with empty stderr and the source hashes identical before and after; this includes the system directory alias retry and the regression for the actual title while preparing / after a failure / on switching tabs.

The initial and final debug / release builds, strict codesign and plist lint all passed; the final release build log is `package-final.log`. The separate QA copy changed only its own bundle id, to `com.tursora.featuresqa.s0913`, and before re-signing its executable was byte-for-byte identical to the production build (QA signing changes the signature data inside the executable); it used its own session / directory view files and sample files and modified no production preferences or workspaces. All smoke, packaging and app operations were serialised through a shared lock.

The interface operations actually carried out this round confirmed:

- In a new instance both options are ticked by default in General; the main window has no terminal panel and the owning process tree has no shell. F4 brings up one zsh, which is reaped after F4 closes it; restarting and restoring a ZIP also starts no shell.
- With the file pane moving from Sample Files into Design, the terminal still shows Started in at the original location while Restart in points at Design; the real `pwd` output is still the original directory. After `exit` the output is kept, Session ended is shown and the button becomes Start in Current Folder; navigating again does not overwrite the ended state, and clicking Start launches a new shell.
- An ordinary double-click on a ZIP enters read-only browsing by default. A broken ZIP shows the file name, the reason for the error and Retry / Open Enclosing Folder; retrying without repairing the file still keeps the original directory and selection, and returning to the enclosing directory works. On a ZIP with a hundred thousand entries the Opening / spinner / Cancel were actually visible, and in another round clicking Cancel succeeded, returning to the original directory with the chosen ZIP still selected.
- A normal exit and reopen restored to Sample.zip/Notes, with the two members, the breadcrumb and the read-only state correct. The first launch into a path inside a broken ZIP under `/private/tmp`, retried after the fix, exposed the alias problem described above, which has been added to the model regressions; after the final repackage, the two broken-ZIP tabs actually launched showed Broken.zip / Notes respectively, and the window title was correct when switching between them. With the original ZIP repaired, clicking Retry entered Notes successfully, with the two members and the read-only state correct; a normal exit and relaunch still kept both tabs, the selected Notes and the location inside it, and the owning process tree had no shell.
