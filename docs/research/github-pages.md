## Implementation

The public product page targets <https://zerolfx.github.io/Tursora/>. It keeps the Chinese static pages in `site/`, the real application screenshots and the Python standard library builder; the only deployment product is `site/dist/`. Every resource stays a relative reference, which suits the `/Tursora/` subpath of a project site.

`.github/workflows/pages.yml` is new: a PR that touches the site or the four source assets runs the static build and the reference checks; when the same kind of change lands on `main`, or is triggered manually on `main`, the build product is handed to GitHub's official Pages Actions to publish. Other branches and PRs neither upload a Pages artifact nor deploy. The build job only reads the repository and the Pages configuration; the deploy job holds `pages: write` / `id-token: write`, depends on a successful build, uses the `github-pages` environment and records the official page URL. The concurrency group keeps an in-flight deployment.

The download button now points at `https://github.com/zerolfx/Tursora/releases/latest`, which resolves to the newest formal release page automatically. The copy keeps the real limits — Apple Silicon, macOS 14+, SHA-256, ad-hoc signing and not notarised — and removes the private-repository login requirement. Direct DMG distribution and drag-to-Applications installation were prepared early as requested, and the page at the time clearly distinguished the released 0.1.0 ZIP from the future DMG; that transitional wording has been removed by the 0.2.0 follow-up described at the top of this document. The description of the ZIP browsing feature is unchanged.
