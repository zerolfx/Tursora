# ZIP 文件夹浏览实验（2026-09-12）

用户希望借鉴 Windows Explorer：打开 ZIP 后按目录层级浏览，并直接打开其中的文件。本实验默认关闭；只有主浏览器确认 `AppPreferences.experimentalZIPBrowsingEnabled` 后，才进入独立 ZIP 浏览窗口。

## 参考与取舍

Microsoft 的[ZIP 与解压说明](https://support.microsoft.com/en-us/windows/experience/storage-filemanagement/zip-and-unzip-files)将 ZIP 作为可打开、可取出单个项目的压缩文件夹。本实验借鉴这种进入归档再选择文件的方式，没有把 Windows 的归档编辑或其他压缩格式支持宣称为已完成。

实现使用独立 AppKit 窗口，标题保留源 ZIP 名称和 `ZIP · Read-only`，上方有 Back、Up 与可点击路径，下方持续解释临时副本、退出时清理、外部编辑不回写 ZIP，以及需要 Save As 保存修改。

首次显式打开时，后台将整个 ZIP 解压到权限为 `0700` 的独占临时目录；不是按条目读取的虚拟文件系统。该选择复用已验证的安全解压路径，且多文件文档或应用包可以找到同目录依赖；代价是大 ZIP 初次打开仍需要完整解压的时间和磁盘空间。没有启用实验、没有打开 ZIP 时不会做这些工作。

浏览保留 ZIP 的原始根结构：多个顶层项目不会额外包一层归档名文件夹；单个顶层文件夹也不会被自动吞掉；空 ZIP 显示空目录。文件夹排序在前，Back、Up、路径点击都限定在本次归档内。普通 ZIP 的现有 Extract 行为不变。

只有对文件的双击、Return 或明确 Open 命令才调用 `NSWorkspace.open`。准备、列目录、选择项目都不会执行文件。外部应用收到的是解压副本的路径，源 ZIP 和压缩前的原文件没有写回路径。窗口关闭后仍保留副本供外部应用继续使用；Tursora 正常退出时清理准备中和已完成会话的自有目录。崩溃或强制终止后的临时目录由系统临时文件生命周期管理，不提供编辑恢复功能。

## 路径与文件保护

解压继续使用 [Finder 归档研究](finder-archives.md) 中的安全路径，包括 libarchive 路径保护、无密码询问、资源叉恢复及下载 quarantine 传递。每次导航和打开文件都同时检查词法路径与解析符号链接后的路径，按完整路径组件判断包含关系。指向归档外部的符号链接可以显示名称，但不能查看目标元数据、导航或传给外部打开器。

临时目录记录创建时的文件 ID；清理前确认该目录仍是原来的自有目录。删除内部符号链接时不跟随其指向，避免清理用户原文件。外部编辑仅限副本，且不会把修改重新压缩回源 ZIP。

## 验证与限制

`ArchiveBrowserSmokeTests.run(completion:)` 提供 37 项检查：默认构造不解压、原 ZIP 身份与只读说明、私有目录权限、单/多根及空包结构、父路径与符号链接逃逸、悬空链接不影响其他条目、层级导航、实际 Return 处理器、空白处双击不打开旧选择、可注入的外部打开器、模拟编辑不改原 ZIP、关闭保留、会话清理、损坏 ZIP 错误和主线程回调。另从普通列表与图标视图的 Open 路径验证实验开关、同一 ZIP 窗口复用，以及关闭开关后恢复解压和精确选中产物。测试不显示窗口、不启动外部应用。

2026-09-12 已在打包应用中通过 computer use 检查独立窗口布局、根结构、嵌套目录和 Back / Up；通过 Return 将文本文件交给 TextEdit，确认显示的是临时目录内的副本。关闭 ZIP 窗口后，TextEdit 中的副本仍可读。底部只读与 Save As 说明完整显示；关闭实验后普通 Open 恢复解压。详见[实机检查记录](computer-use-2026-09-12.md)。

当前不支持归档内编辑、回写、密码、多格式归档、归档内搜索、拖出文件、Quick Look 或原 ZIP 外部改变后的自动重载。归档内嵌套 ZIP 会作为普通文件交给系统关联应用；不会自动递归建立另一个浏览会话。
